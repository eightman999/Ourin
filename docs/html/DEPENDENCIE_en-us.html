Ourin Dependencies Documentation

Last Updated: July 13, 2026 Version: 1.2.0

Overview

The Ourin project adopts a design with minimal dependencies. This document describes all dependencies, their purposes, and security considerations.

Main Application (Swift/SwiftUI)

External Dependencies

None - The Ourin main application has no external dependencies.

Security Considerations

Secure Coding Practices

  1. No External HTTP Dependencies
  2. No automatic downloads of third-party libraries

  3. All dependencies are either bundled or system-provided

  4. Character Encoding Security

  5. CP932/UTF-8 conversion uses system libiconv

  6. Input validation for ghost dictionaries

  7. Plugin Isolation

  8. Plugins run in separate XPC processes

  9. No direct access to sensitive files

  10. File System Access

  11. Non-sandboxed but respects user permissions

  12. Ghost data stored in standard user locations

  13. Network Security

  14. SSTP over TCP/HTTP (no custom protocol)
  15. XPC for local inter-process communication

Threat Model

Threat Mitigation
Malicious ghost dictionary Input validation, parser guards
Malicious plugin XPC isolation, capability restrictions
Buffer overflow in yaya_core Memory-safe Swift wrapper, bounds checking
Network sniffing SSTP is application-level, users can use SSH tunnel
Supply chain attack Minimal dependencies, most bundled or system-provided

Update Policy

Swift/macOS Updates

The project targets macOS 12.0 LTS and later versions of Swift.

When macOS/Swift versions are updated: 1. Test with new version 2. Update version requirements if needed 3. Document breaking changes 4. Provide migration guide for users

Dependency Updates

For bundled dependencies like nlohmann/json: 1. Monitor upstream for security updates 2. Test compatibility before updating 3. Document changes in CHANGELOG 4. Provide release notes to users

Building Without External Dependencies

Fully Offline Build

To build Ourin without downloading any external dependencies:

# All dependencies already in repository:
xcodebuild -project Ourin.xcodeproj -scheme Ourin build

# Or for yaya_core:
cd yaya_core
./build.sh  # Uses system CMake, nlohmann/json is local

Note: Ghidra must be installed separately if using DevTools Migrator.
