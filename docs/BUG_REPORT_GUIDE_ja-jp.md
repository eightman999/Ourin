# バグ報告ガイド

更新日: 2026-10-25。[English](BUG_REPORT_GUIDE_en-us.md) / [既知の問題](KNOWN_ISSUES_ja-jp.md)

[既存Issue](https://github.com/eightman999/Ourin/issues)と既知の問題を確認し、同じ症状がなければ[Bug reportテンプレート](https://github.com/eightman999/Ourin/issues/new?template=bug_report.md)を使ってください。分からない項目は「不明」、実行できなかった確認は「未実施」で構いません。

## 最低限必要な情報

- Ourinの版・ビルド番号（About Ourinで確認）、配布元または開発commit。
- macOSの版、Intel/Apple Silicon、分かる場合はRosetta実行の有無。
- ゴーストの公開名・版・配布URL、SHIORIの種別・版（分かる範囲）。関連するshell、balloon、SAORI、plugin。
- 再現手順、期待する動作、実際の動作、発生頻度と時刻・タイムゾーン。
- 起動時、会話時、保存時、再起動後など、問題が起きる場面。問題を調べるために実セーブデータを削除する必要はありません。

ゴースト名や配布URLを公開できない場合はその旨を記載し、再配布可能な最小fixtureでの再現を相談してください。私的な辞書、会話内容、NAR、セーブファイルを報告の必須資料にはしません。

## ログを取得する

以下は現行ソースで確認した操作です。配布版や言語設定で表示が異なる場合は、利用版と表示名を報告してください。

### 必要な行だけコピーする

1. Ourinの`Settings...`（設定、⌘,）を開き、`Logging & Diagnostics`を選択します。
2. 発生時刻に合う`Since`と適切な`Subsystem`を選び、「更新」を押します。
3. 発生前後の関連行を選択して「コピー」を押し、共有用のテキストファイルへ貼り付けます。共有前に次節の除去を行います。

### 設定画面からExportする

設定ウィンドウの上部にある共有アイコン（上向き矢印、ツールチップ`Export`）で`OurinDiagnostics.txt`を作成し、Finderで表示します。ファイルは一時ディレクトリにあるため、必要な抜粋を別の共有用ファイルへ保存してください。

**取得範囲は`jp.ourin.devtools`の直近24時間のみ**です。表示中のログフィルタとは連動せず、SHIORI/helperの全ログや環境情報をまとめる機能ではありません。**Debugメニューの「診断情報をエクスポート」は現状、日時文のみ**なので、そちらの出力を完全な診断情報として送らないでください。エントリが0件なら、その旨と再現時刻を記載します。

### ファイルログが必要な場合

1. 設定の`General`にある「ログ設定」で「ファイルへのログ出力を有効化」をオンにします。
2. 表示された「ログ出力先」を確認し、「設定を保存」を押します。既定はアプリのホームディレクトリ配下の`Library/Logs/Ourin/ourin.log`です。実際の場所は画面の値を優先してください。
3. 発生時刻を記録して一度再現し、指定ファイルから該当する前後の行だけを共有用コピーへ抜き出します。
4. 調査が終わったらトグルをオフにし、「設定を保存」を押します。保存先の既存ログや実ゴーストデータを削除する必要はありません。

ファイルログは`Log`経由の記録であり、全OSLog、helperのstderr、第三者コードの出力を網羅しません。ファイルが生成されない場合も、取得不可として報告できます。

## 共有前に確認する

GitHub Issueは公開されます。出力の自動匿名化は保証していません。**元データを変更せず、共有用コピー**を読んで以下を取り除いてください。

- APIキー、トークン、パスワード、Cookie、Authorizationヘッダ、秘密鍵、`.env`の内容。
- `/Users/実名/...`などの個人パス、ユーザー名、メールアドレス、端末ID。例: `/Users/<user>/...`へ置換。
- 私的な会話・辞書・保存内容、クリップボード、外部通信の本文、非公開URLやホスト名。
- スクリーンショットの他アプリ、通知、アカウント名。必要な範囲だけ切り出します。

エラーコード、イベント名、時刻の前後関係、拡張子は可能な範囲で残すと調査に役立ちます。秘匿が難しい場合は添付せず、症状だけを報告してください。診断のための`sysdiagnose`全体、ホームフォルダ、ghostフォルダ一式の公開は不要です。

## クラッシュ・応答停止

終了したプロセス名（Ourin / yaya_core / satori_core / OurinShioriXPCServiceなど）、発生時刻、直前の操作、Ourin本体も終了したかを記載します。macOSのコンソールで該当クラッシュレポートが見つかる場合は、版・OS・アーキテクチャ、Exception/Termination Reason、該当スレッドの抜粋を共有用コピーから添付してください。個人パスや識別子を除去し、レポートがなければ「取得不可」で構いません。

応答停止の場合は待った時間、画面だけか会話・終了操作も止まったかを記載します。診断のために長時間繰り返し停止させたり、未保存データを削除したりする必要はありません。

## 実装根拠と残件

操作名・取得範囲は[ContentView.swift](../Ourin/ContentView.swift)、[DevToolsCommands.swift](../Ourin/DevTools/DevToolsCommands.swift)、[Log.swift](../Ourin/Utils/Log.swift)の2026-10-25時点の実装を確認しています。これはGUI実機操作の再検証ではありません。環境情報の一括Export、Export入口の統一、匿名化機能は[#104](https://github.com/eightman999/Ourin/issues/104)の追加検討・検証対象です。
